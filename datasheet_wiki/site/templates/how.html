How this wiki is generated

This site was built by datasheet-wiki from {{ meta.source_name }} ({{ meta.page_count }} pages) using the {{ meta.compute }} tier (enrichment backend {{ meta.backend }}{% if meta.model %}, model {{ meta.model }}{% endif %}).

Every part of a section page is derived from the original PDF. Here is where each piece comes from:

Sections & sidebar tree The PDF's built-in outline (table of contents) read with PyMuPDF. Each entry owns a page range; if the PDF has no outline, pages are grouped in fixed blocks. always local · no LLM
Source page images Each page is rasterised at {{ meta.dpi }} DPI and shown near the top of its section, captioned with the page number, so you can always check the generated content against the original. always local · no LLM
Cross-reference links "see Section 4.3", "Table 10-1" and "page 42" are turned into wiki links by matching them against the section tree, combined with the hyperlinks the datasheet authors already embedded in the PDF. always local · no LLM
Summary & keywords {% if meta.backend == 'none' %}Extractive heuristics: the first substantial sentences of the section, plus frequency-ranked identifiers as keywords. Generated from the section's page range (shown next to each summary).{% else %}Written by the {{ meta.backend }} model from the section's text (the page range is shown next to each summary), on top of the heuristic baseline.{% endif %} {{ 'local heuristics' if meta.backend == 'none' else ('local LLM' if meta.backend == 'ollama' else 'cloud LLM') }}
Registers & bit-fields Heuristic detection of "NAME – … Register" headings and "Bit n – FIELD" rows via regular expressions{% if meta.backend != 'none' %}, then refined into structured tables by the LLM{% endif %}. {{ 'local heuristics' if meta.backend == 'none' else 'heuristics + LLM' }}
Code examples Code-like blocks (C/assembly) detected in the page text{% if meta.backend != 'none' %}, plus minimal usage examples generated by the LLM{% endif %}. All examples are also collected on the Code examples page. {{ 'local heuristics' if meta.backend == 'none' else 'heuristics + LLM' }}
Formatted text The raw PDF text reflowed into real paragraphs (hard line breaks joined, words de-hyphenated), with headings, bold and bullet lists recovered from the font metadata. always local · no LLM
Tables Scattered table cells (e.g. a register's Bit / 7 / 6 / 5 / 4 column) are combined onto one line and tucked into a collapsed code block; a page that is entirely a table is flagged with a link to its image. always local · no LLM
Figures Embedded raster images are extracted, and vector diagrams are cropped out of the blank gaps between paragraphs that actually contain drawing, then embedded inline. always local · no LLM
Search A full-text tf-idf index is prebuilt and shipped as a JavaScript file so search works even over file://{% if meta.semantic %}; this build also generates a local embedding index (a building block for the planned semantic Q&A — the search page itself is full-text){% endif %}. {{ 'local (+ embeddings)' if meta.semantic else 'always local' }}

Compute tiers

The same generator runs at three levels of effort — this wiki used {{ meta.compute }}:

  • small — no LLM at all; heuristics only. Runs on any laptop.
  • medium — a local LLM via Ollama (nothing leaves your machine).
  • large — a cloud LLM API for the best summaries, register extraction and code examples.

Cross-reference links, register/figure/table handling, page images and search are produced locally in every tier; only the summary, structured register extraction and generated code examples change with the backend.
